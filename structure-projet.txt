## Notes sur l'Organisation

### Structure des Composants
- **common/** : Composants UI réutilisables (boutons, inputs, modals, etc.)
- **layout/** : Composants de mise en page (header, sidebar, footer)
- **forms/** : Formulaires spécifiques métier avec validation
- **cards/** : Cartes d'affichage pour différentes entités
- **maps/** : Composants cartographiques (Mapbox)
- **charts/** : Graphiques et visualisations statistiques
- **search/** : Système de recherche et filtres
- **notifications/** : Gestion des notifications
- **ia/** : Composants d'intelligence artificielle

### Structure des Features
Chaque feature (dossiers, personnes, signalements, etc.) contient :
- **components/** : Composants spécifiques à la feature
- **hooks/** : Hooks personnalisés
- **services/** : Logique métier et appels API
- **store/** : State management (Redux slices)
- **types/** : Types TypeScript
- **utils/** : Utilitaires spécifiques

### Structure des Pages
Organisation par rôle utilisateur :
- **public/** : Pages accessibles sans authentification
- **auth/** : Pages d'authentification
- **citizen/** : Dashboard citoyen
- **moderator/** : Interface modérateur
- **operator/** : Interface opérateur de saisie
- **authority/** : Interface autorités (police/gendarmerie)
- **ngo/** : Interface ONG
- **admin/** : Administration d'organisation
- **super_admin/** : Administration système
- **errors/** : Pages d'erreur

### Services Externes
- **Supabase** : Base de données, authentification, realtime
- **Cloudinary** : Gestion des images
- **Mapbox** : Cartographie
- **Firebase** : Notifications push (FCM)

### Tests
- **unit/** : Tests unitaires des composants/hooks/utils
- **integration/** : Tests d'intégration des features
- **e2e/** : Tests end-to-end (Cypress/Playwright)

### Configuration
- Fichiers de configuration pour tous les outils
- Variables d'environnement par environnement
- Configuration TypeScript avec paths aliases
- Configuration Tailwind CSS personnalisée

### Documentation
Documentation complète dans le dossier `docs/` couvrant l'architecture, l'API, le déploiement et les guides utilisateurs.

### CI/CD
GitHub Actions pour :
- Tests automatiques
- Déploiement continu
- Vérification du code (linting)
- Build et optimisation
