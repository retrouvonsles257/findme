RETROUVONSLES

Application de recherche de personnes disparues

DOCUMENTATION COMPLÈTE

Rôles, Permissions et Actions des Utilisateurs

Version 1.0 - Janvier 2026

Documenteur : IBRAHIM ABAKAR KORI.

1. INTRODUCTION ET VUE D'ENSEMBLE

Ce document présente de manière exhaustive tous les rôles utilisateurs
de l'application RetrouvonsLes, leurs permissions, restrictions et
actions possibles.

L'application utilise un système de rôles hiérarchiques avec 8 niveaux
d'accréditation (0 à 7), chaque niveau héritant des permissions du
niveau inférieur et ajoutant des capacités supplémentaires.

NIVEAU 0 - CITOYEN STANDARD

Informations générales

  -----------------------------------------------------------------------
  Niveau d'accréditation              0
  ----------------------------------- -----------------------------------
  Nom du rôle                         citoyen_standard

  Type de compte                      Grand Public

  Statut par défaut                   actif
  -----------------------------------------------------------------------

Utilisateur grand public standard sans vérification d'identité

Permissions détaillées

Consultation :

-   Voir tous les dossiers de disparition marqués comme publics
    (visible_public = TRUE)

-   Consulter les photos publiques approuvées des personnes disparues

-   Accéder à la carte interactive des disparitions en cours

-   Filtrer les dossiers par région, type (enfant/adulte), statut

-   Voir les détails publics des dossiers : nom, photo, âge, description
    physique, dernière localisation connue

-   Consulter les alertes publiques diffusées dans leur zone
    géographique

-   Accéder aux messages de prévention et sensibilisation

Signalement :

-   Créer des signalements d'observations de personnes disparues

-   Fournir des informations : description, localisation GPS, photo
    optionnelle, date/heure

-   Signaler via différents canaux : application mobile, application web

-   Les signalements sont soumis avec statut 'en_attente' de validation

-   Recevoir une confirmation de réception du signalement

Notifications :

-   Recevoir des alertes géolocalisées pour les disparitions dans leur
    zone

-   S'abonner à des notifications pour des zones géographiques
    spécifiques

-   Recevoir des notifications de type 'nouvelle_alerte' si dans le
    rayon de diffusion

-   Consulter l'historique de leurs notifications reçues

Profil :

-   Voir et modifier leur propre profil (nom, prénom, email, téléphone)

-   Gérer leurs préférences de notifications

-   Configurer les zones géographiques d'intérêt pour les alertes

-   Consulter l'historique de leurs propres signalements

-   Voir le statut de traitement de leurs signalements

Interdictions :

-   INTERDIT : Créer des dossiers de disparition

-   INTERDIT : Modifier des dossiers existants

-   INTERDIT : Valider ou modérer des signalements

-   INTERDIT : Accéder aux dossiers non publics ou confidentiels

-   INTERDIT : Voir les commentaires confidentiels des autorités

-   INTERDIT : Créer ou diffuser des alertes officielles

-   INTERDIT : Accéder aux fonctionnalités d'analyse IA avancées

-   INTERDIT : Voir les statistiques complètes du système

-   INTERDIT : Gérer d'autres utilisateurs

Politiques de sécurité RLS

Les politiques suivantes sont appliquées au niveau de la base de données
PostgreSQL :

-   Peut voir uniquement les dossiers avec visible_public = TRUE

-   Peut voir uniquement les photos avec visible_public = TRUE ET
    approuvee = TRUE

-   Peut voir uniquement ses propres signalements (id_utilisateur =
    auth.uid())

-   Peut voir uniquement ses propres notifications (id_utilisateur =
    auth.uid())

-   Ne peut pas voir les commentaires marqués comme confidentiels

Actions enregistrées dans le journal d'audit

Toutes les actions suivantes sont automatiquement enregistrées :

-   connexion - Connexion à l'application

-   deconnexion - Déconnexion de l'application

-   creation_signalement - Création d'un nouveau signalement

-   modification_profil - Modification de son profil utilisateur

-   upload_photo - Upload d'une photo dans un signalement

NIVEAU 1 - CITOYEN VÉRIFIÉ

Informations générales

  -----------------------------------------------------------------------
  Niveau d'accréditation              1
  ----------------------------------- -----------------------------------
  Nom du rôle                         citoyen_verifie

  Type de compte                      Grand Public

  Statut par défaut                   actif
  -----------------------------------------------------------------------

Citoyen avec identité vérifiée (CNI, passeport validé)

Permissions détaillées

Hérite De :

Toutes les permissions de citoyen standard

Consultation :

-   Mêmes droits de consultation que le citoyen standard

-   Voir tous les dossiers publics avec les mêmes filtres

Signalement :

-   Créer des signalements avec priorité de traitement plus élevée

-   Les signalements sont marqués avec priorite_traitement = 'moyenne'
    au lieu de 'basse'

-   Peut joindre plusieurs photos (jusqu'à 5) par signalement

-   Peut fournir des informations plus détaillées (documents d'identité
    si pertinent)

-   Les signalements sont traités plus rapidement par les modérateurs

Notifications :

-   Mêmes droits de notification que le citoyen standard

-   Peut recevoir des notifications prioritaires pour cas critiques dans
    leur zone

-   Accès à un canal de notification prioritaire pour alertes critiques

Profil :

-   Mêmes droits de gestion de profil que le citoyen standard

-   Badge 'Vérifié' visible sur leur profil

-   Historique de leurs signalements avec score de fiabilité visible

-   Peut voir leur score de contribution (nombre de signalements
    validés)

Avantages :

-   Score de fiabilité initial plus élevé pour leurs signalements

-   Signalements traités en priorité par les modérateurs

-   Crédibilité accrue auprès des autorités

-   Peut participer à des programmes de bénévolat de l'application

Interdictions :

-   INTERDIT : Créer des dossiers de disparition

-   INTERDIT : Modifier des dossiers existants

-   INTERDIT : Valider des signalements d'autres utilisateurs

-   INTERDIT : Accéder aux dossiers confidentiels

-   INTERDIT : Voir les commentaires des autorités

-   INTERDIT : Créer des alertes officielles

-   INTERDIT : Accéder aux outils d'analyse IA

-   INTERDIT : Gérer d'autres utilisateurs

Politiques de sécurité RLS

Les politiques suivantes sont appliquées au niveau de la base de données
PostgreSQL :

-   Mêmes politiques RLS que le citoyen standard

-   Peut voir uniquement les dossiers publics

-   Peut voir uniquement ses propres signalements

-   Ne peut pas accéder aux données confidentielles

Actions enregistrées dans le journal d'audit

Toutes les actions suivantes sont automatiquement enregistrées :

-   Mêmes actions que citoyen standard +

-   creation_signalement - Signalements avec priorité moyenne

-   upload_photo - Peut uploader jusqu'à 5 photos par signalement

Politiques de sécurité RLS

Les politiques suivantes sont appliquées au niveau de la base de données
PostgreSQL :

-   get_user_niveau_acces(auth.uid()) >= 2 requis pour certaines
    opérations

-   Peut voir les dossiers de son organisation uniquement

-   Peut modifier uniquement les dossiers où id_utilisateur_createur =
    auth.uid()

-   Ne peut pas accéder aux commentaires confidentiels de niveau
    supérieur

Actions enregistrées dans le journal d'audit

Toutes les actions suivantes sont automatiquement enregistrées :

-   creation_dossier - Création d'un nouveau dossier de disparition

-   modification_dossier - Modification d'un dossier qu'il a créé

-   upload_photo - Upload de photos dans un dossier

-   connexion / deconnexion

Workflow type

1. L'opérateur reçoit un signalement de disparition (famille, police)

2. Il crée un nouveau dossier dans le système

3. Il saisit toutes les informations fournies

4. Il uploade les photos disponibles

5. Le dossier est créé avec statut 'en_cours' et niveau_urgence initial

6. Un superviseur (modérateur ou officier) doit valider et compléter le
dossier

NIVEAU 3 - MODÉRATEUR

Informations générales

  -----------------------------------------------------------------------
  Niveau d'accréditation              3
  ----------------------------------- -----------------------------------
  Nom du rôle                         moderateur

  Type de compte                      Autorité

  Statut par défaut                   actif

  Organisation                        Requis
  -----------------------------------------------------------------------

Modérateur de signalements et contenu (niveau intermédiaire)

Permissions détaillées

Hérite De :

Permissions de consultation etendues

Consultation :

-   Voir TOUS les signalements en attente de validation (statut
    'en_attente')

-   Accéder à la liste complète des signalements de toutes sources

-   Consulter les signalements validés et invalidés

-   Voir les signalements marqués comme spam ou doublons

-   Accéder aux photos uploadées en attente d'approbation

-   Consulter les résultats d'analyse IA sur les signalements

-   Voir le score de fiabilité des signaleurs

-   Accéder aux métadonnées des signalements (IP, device, timestamps)

Moderation :

-   PEUT valider des signalements (changer statut de 'en_attente' à
    'valide')

-   PEUT invalider des signalements non pertinents (statut 'invalide')

-   PEUT marquer des signalements comme spam (statut 'spam')

-   PEUT identifier et marquer les doublons (statut 'doublonne')

-   PEUT approuver ou rejeter les photos uploadées par le public

-   PEUT ajouter des notes de modération sur les signalements

-   PEUT ajuster le niveau de priorité de traitement

-   PEUT transférer des signalements importants aux autorités
    compétentes

Gestionphotos :

-   Approuver les photos pour diffusion publique (approuvee = TRUE,
    visible_public = TRUE)

-   Rejeter les photos inappropriées ou de mauvaise qualité

-   Catégoriser les photos par type (portrait, lieu, objet, etc.)

-   Évaluer la qualité des images (excellente, bonne, moyenne, faible)

-   Flouter ou masquer des éléments sensibles si nécessaire

Workflow :

-   Filtrer les signalements par priorité et source

-   Examiner chaque signalement pour pertinence et qualité

-   Vérifier la cohérence avec le dossier de disparition associé

-   Valider les signalements crédibles pour transmission aux autorités

-   Rejeter le spam, les fausses alertes, les contenus inappropriés

-   Documenter les raisons de validation/invalidation

Interdictions :

-   INTERDIT : Créer des dossiers de disparition

-   INTERDIT : Modifier le contenu des dossiers de disparition

-   INTERDIT : Changer le statut des dossiers (retrouvé, classé, etc.)

-   INTERDIT : Créer ou diffuser des alertes officielles

-   INTERDIT : Accéder aux outils de coordination des enquêtes

-   INTERDIT : Gérer les utilisateurs ou organisations

-   INTERDIT : Configurer les paramètres système

Politiques de sécurité RLS

Les politiques suivantes sont appliquées au niveau de la base de données
PostgreSQL :

-   get_user_niveau_acces(auth.uid()) >= 3 pour voir tous les
    signalements

-   Peut voir les signalements de toutes les organisations

-   Peut modifier les signalements (validation/invalidation)

-   Ne peut pas voir les commentaires de coordination de niveau
    supérieur

Actions enregistrées dans le journal d'audit

Toutes les actions suivantes sont automatiquement enregistrées :

-   validation_signalement - Validation d'un signalement

-   modification_signalement - Changement de statut
    (valide/invalide/spam)

-   upload_photo - Approbation ou rejet de photos

-   connexion / deconnexion
